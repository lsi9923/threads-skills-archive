# /goal 프롬프트 생성기

## 언제 쓰나
사용자가 "X 하는 골 프롬프트 만들어줘"처럼 **작업 지시문 자체**를 요청할 때.
코드를 바로 쓰는 게 아니라, 다른 에이전트(Codex·Claude·GJC·OmO)에게 넘길 지시문을 만드는 작업이다.

## 핵심 원칙
단순 지시문이 아니라 **목표 선언문 + 완료 조건 + 검증 증거 + 제약 조건 + 중단 조건**을 만든다.
그래야 받은 에이전트가 중간에 물어보지 않고 스스로 판단하며 끝까지 간다.

## 절차

### 1단계 — 주제 분석
사용자 입력에서 다음 8개 항목 중 **비어 있는 것**을 찾는다.
A. 최종 목표 · B. 결과물 형태 · C. 완료 조건 · D. 검증 방법
E. 제약 조건 · F. 작업 범위 · G. 우선순위 · H. 막힐 때 행동

### 2단계 — 질문 (한 번에 3개 이하)
- 선택지 중심으로 묻는다. (예: "결과물은 (1) 코드 수정 (2) 새 파일 (3) 문서 중 뭐야?")
- 한 번에 너무 많이 묻지 않는다.
- 사용자가 짧게 답해도 **추측해서 채우지 않는다.**
- 끝까지 모르는 항목은 `[가정]`으로 명시한다.

### 3단계 — 최종 프롬프트 작성
아래 골격을 그대로 쓴다.

````markdown
## Background
(왜 이 작업을 하는가 — 2~3문장)

## Objective
(끝났을 때 무엇이 되어 있는가 — 한 문장)

## Scope
- 포함: ...
- 제외: ...

## Requirements
1. ...
2. ...

## Success Criteria
- [ ] 검증 가능한 형태로 쓴다 (명령·파일·수치)
- [ ] ...

## Verification Evidence
(완료를 어떻게 증명하는가 — 실행 로그, 스크린샷, 테스트 출력, 파일 해시)

## Constraints
- 하지 말 것: ...
- 지켜야 할 것: ...

## Decision Rules
(판단이 갈릴 때 기준. 예: "속도보다 정확성 우선")

## Stop Conditions
(중단하고 보고해야 하는 상황. 예: "인증 실패 3회", "예상 밖 파일 삭제 위험")
````

### 4단계 — 인도
- 최종 결과는 **바로 복사할 수 있는 코드블록**으로 준다.
- 완료 조건에 숫자·날짜가 들어가면 근거를 함께 적는다. **근거 없는 수치를 만들지 않는다.**

## 체크리스트
- [ ] 8개 항목이 모두 채워졌거나 `[가정]`으로 표시됐다
- [ ] Success Criteria 가 눈으로 확인 가능한 형태다
- [ ] Stop Conditions 가 비어 있지 않다
- [ ] 사용자가 답하지 않은 것을 임의로 채우지 않았다
