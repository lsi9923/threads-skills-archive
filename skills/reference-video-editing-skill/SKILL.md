# 레퍼런스 영상 편집기 자동 제작

## 언제 쓰나
편집을 잘 모르는데 특정 채널/영상처럼 편집하고 싶을 때. 사람이 매번 손대지 않고 **규칙으로 자동화**할 때.

## 전체 흐름 (7단계)

### 1. 레퍼런스 분해
레퍼런스 영상 3~4개를 받아 **장면 단위**로 분석한다.

| 분석 항목 | 기록할 것 |
|---|---|
| 컷 전환 | 컷이 바뀌는 간격(초) |
| 자막 | 글꼴·크기·색·위치 |
| 강조 자막 | 뜨는 순간, 커지는 방식 |
| 효과음 | 들어가는 타이밍 |
| 배경음 | 깔리는 구간, 볼륨 변화 |
| 자료화면 | 등장 방식, 화면 대비 크기 |
| 화면 확대 | 줌 구간과 배율 |
| 인트로/아웃트로 | 길이와 구성 |

결과물은 **'편집 규칙집' 문서 1개**로 정리한다.

### 2. 편집 프로그램 제작
규칙집을 그대로 실행하는 프로그램을 만든다 (예: Python + ffmpeg).
- 하드코딩 금지: 규칙은 **설정 파일**(JSON/YAML)로 분리한다.
- 규칙을 바꾸면 코드를 안 고쳐도 결과가 바뀌어야 한다.

### 3. 스킬로 저장
다음부터 한 문장으로 부를 수 있게 스킬로 등록한다.

### 4. 편집 순서 (반드시 이 순서)

1. **받아쓰기** — 원본 음성을 전부 텍스트로.
2. **교정 대본** — 말 더듬은 곳, 같은 말 반복, 긴 정적을 제거. **말의 내용과 말투는 바꾸지 않는다.**
3. **컷 편집** — 교정 대본에 있는 말만 남긴다.
4. **자막·효과음** — 규칙집대로 넣는다.
5. **자료화면** — 발언 내용에 맞는 공식 화면·기사 제목 등을 찾아 넣고 **출처를 작게 표기**한다.
6. **출력** — mp4로 저장.

### 5. 자가 검수 (납품 전 필수)

- [ ] 자막 오타
- [ ] 소리가 끊기는 곳
- [ ] 화면이 멈추는 곳
- [ ] 개인정보가 화면에 보이는 곳 (주소·전화·이메일·계정명·알림)

발견하면 **고친 뒤에** 결과를 보고한다.

### 6. 피드백 반영
결과를 보고 "아쉬운 점"을 말하면 그 내용을 **규칙집에 추가**하고 다음 편집부터 자동 반영한다. 코드가 아니라 규칙집을 고친다.

### 7. 이후 호출
"드라이브에 영상 올렸어, 편집해줘" 한 문장으로 끝까지 진행.
드라이브가 연결돼 있지 않으면 연결 방법부터 안내한다.

## 하지 말 것
- 말의 내용·말투를 임의로 바꾸지 않는다 (요약·윤문 금지).
- 출처 없는 자료화면을 넣지 않는다.
- 검수 없이 납품하지 않는다.

## 준비물 체크
- [ ] 레퍼런스 영상 3~4개 (품질이 결과를 좌우한다)
- [ ] ffmpeg 설치
- [ ] 받아쓰기 도구(whisper 등)
- [ ] 원본 영상 접근 경로

---

**가장 중요한 건 레퍼런스 영상 품질이다.** 좋은 레퍼런스가 없으면 규칙집이 부실해진다.
