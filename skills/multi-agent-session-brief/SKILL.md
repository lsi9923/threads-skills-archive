# 멀티 세션 역할 분담 브리핑

## 언제 쓰나
한 작업을 여러 에이전트에 나눠 맡길 때. 각자 같은 파일을 동시에 고치거나, 서로 결과를 기다리다 멈추는 사고를 막는다.

## 역할 구분 원칙
| 역할 | 하는 일 | 하지 않는 일 |
|---|---|---|
| **머리(판단)** | 원인 판단, 방향 결정, 결과 검수 | 직접 브라우저·파일 대량 조작 |
| **실행(꼬봉)** | 지시받은 순서대로 실행, 증거 수집 | 방향을 스스로 바꾸기 |
| **수집(조사)** | 링크·자료 대량 수집, 반복 검증 | 최종 판정 |

한 에이전트에 판단과 실행을 동시에 맡기면, 실패했을 때 원인을 자기가 감싸게 된다.

## 브리핑 형식 (이 5개만 쓰면 된다)

````markdown
## 역할
너는 [판단/실행/수집] 담당이다.

## 목표
(끝났을 때 남아 있어야 하는 파일·상태 — 한 문장)

## 입력
- 경로: ...
- 이미 있는 것: ...
- 없는 것: ...

## 순서
1. ...
2. ...

## 성공 기준
- 파일: (경로, 최소 크기)
- 확인 명령: ...

## 하지 말 것
- 다른 에이전트 결과 폴더 참조·복사 금지
- 확인 안 된 것을 "완료"로 보고 금지
````

## 충돌 방지 규칙
- **폴더 분리**: 에이전트마다 결과 폴더를 따로 준다. 남의 폴더를 읽거나 복사하지 않는다.
- **같은 파일 동시 편집 금지**: 한 파일은 한 에이전트만 쓴다.
- **오류 시**: 먼저 "이어서"를 보내 재개시킨다. 일을 빼앗지 않는다.
- **2회 수정 후에도 실패**하면 그때 사용자에게 넘긴다.

## 완료 보고 형식
```
[완료] 목표: ...
산출물: (경로, 크기, 수정시각)
검증: (실행한 확인 명령과 출력)
미해결: ...
```

## 체크리스트
- [ ] 역할이 판단/실행/수집 중 하나로 명확한가
- [ ] 성공 기준이 파일 경로와 크기로 적혀 있는가
- [ ] 하지 말 것에 폴더 분리 규칙이 있는가
